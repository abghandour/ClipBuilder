REVISE

1. **Critical — D1/D7, S1: the watchdog cannot guarantee termination.** D1 checks a flag only at bridged calls or an unspecified polling hook, then proposes abandoning/releasing the context. A pure infinite loop never reaches either; dropping a reference cannot unwind active evaluation, and the serial queue remains occupied. Bridge-result caps also do not bound the JavaScript heap. Replace abandonment with a killable worker process, or first prove an acceptable engine termination mechanism and memory policy. WebKit exposes execution limits in its [private API header](https://github.com/WebKit/WebKit/blob/main/Source/JavaScriptCore/API/JSContextRefPrivate.h); do not assume that is a supported public macOS contract. Gate S1 on stopping call-free loops, recursion and allocation storms, then successfully running another script.

2. **Critical — D3.3: specify an implementable async bridge without lock cycles.** `BuilderTools.swift:58` is `@MainActor async throws` for every tool, not just prerequisites. A `DispatchQueue.main.sync` closure cannot directly await it. Blocking inside that closure deadlocks the actor; main-actor completion touching the same VM can also block because [JavaScriptCore serializes VM access](https://developer.apple.com/documentation/javascriptcore/jsvirtualmachine). Marshal arguments before crossing, schedule an owned MainActor task, transfer only Sendable bytes/results, and block only the dedicated worker. Never synchronously wait for that worker from main. Keep context/value access, error construction and destruction on its owner; document cancellation and exactly-once completion races.

3. **Critical — D3.5/D6: validation is not side-effect-free.** D6 says both that submission evaluates the script and that nothing executes on submit. A copied timeline does not isolate `BuilderPrerequisites.perform` (`BuilderPrerequisites.swift:97–132`): it writes receipts and invokes services against the captured database. Use syntax/header validation plus a strictly isolated evaluation capability with no production prerequisite adapters, run-record writes or live hydration ownership. Missing prerequisites should report “requires user-run validation,” not execute automatically or claim full validation. Require explicit sample values for mandatory clip/scene parameters without defaults. Test zero production writes across all three submission attempts.

4. **High — D2/D4/D7: prerequisite declarations cannot satisfy existing authorization.** A `requires` array of names cannot populate the exact commands checked by `confirmedPrerequisites.contains(command)` in `BuilderTools.swift:111–124`. That code also forbids ensures after mutations; the D2 example puts `ensure_transcript` after edits. Declare concrete video targets, possibly resolved from parameters before confirmation, enforce the prefix rule, and fix the example. Reconcile the 10/60-second script deadline with the separate 600-second prerequisite budget and mandatory cancellation drain (`BuilderPrerequisites.swift:36–68`). Report saved effects even after timeout, dismissal or profile changes; do not release the session before draining.

5. **High — D1/D2/D3/D7: direct tools reuse omits terminal policy and auditing.** `BuilderTools.swift:148–150` deliberately leaves direct callers' sessions usable after budget errors. `BuilderMCPServer.swift:58–135` supplies terminal failure, result sanitization, event production and log charging. Simply calling tools and freezing on return lets JavaScript catch a budget exception and retain an applicable preview. Extract/reuse an execution coordinator in S1: revoke admission on cancellation/budget/uncaught errors, drain the complete callback, record bounded redacted events, then fail or freeze. A terminal condition must remain terminal even when JavaScript catches its exception.

6. **High — D2, S1: the illustrated API is not the existing wire format.** `BuilderCommand.swift:626–639` accepts steps containing `command` and optional `bind`; D2 passes flat `op` objects. `CommandOutcome` uses synthesized enum Codable (`ScriptRunner.swift:3–17`), not `{ refused: true, code, reason }`. Define and test explicit step lowering and outcome projection, including warnings, actual values and created IDs. `BuilderTools.commandSchema` is private (`:229`) and contains a `query` operation that collides with the proposed query convenience. Expose shared schema metadata, reserve special method names, and preserve mode/prerequisite gates. Define pagination for summary conveniences; current summary exposes a numeric `tracks` and separate `trackLabels`.

7. **High — D1/D2, Tests: recoverable semantics remain contradictory and partly stale.** D1 says every refusal ends the run, then says the script may continue. Current `BuilderTools.swift:139–140` opts into recovery; `BuilderScriptSession.run` defaults to terminal local behavior and keeps timeout/limit/cancellation terminal even with recovery. `ScriptRunner.swift:55–127` restores bindings on rollback and replaces an entire binding namespace on successful rebinding. Explicitly choose the tools' recovery mode for JavaScript and define caught versus uncaught refusals and diagnostic versus committed outcomes. The older `Scriptable-Builder-Plan.md` “Validation and execution” and Phase5 “Validation, diff and atomicity” text is stale relative to this code. Add cross-list rebind/rollback, stale-revision and terminal-error-caught-in-JS tests.

8. **High — D5/D6, S2: `executedSteps` cannot reconstruct the promised export.** It is a flat array (`BuilderTools.swift:14,121,140`), excludes refused edit lists, includes prerequisite calls, and stores neither call boundaries nor returned IDs. Local execution bypasses tools (`WizardSheetModel.swift:341–358`), while agent tools leave scope after producing diff lines (`:622`). Retain a bounded replay transcript for both paths, with successful list boundaries, prerequisite metadata and ID-producing outcomes, before offering Save. Rewrite later references to newly created UUIDs as bindings; parameterizing only baseline clips leaves generated IDs and baseline sound/overlay/crop IDs unusable. Preserve binding replacement order and split ensures into separate calls. Restrict export eligibility when equivalent replay cannot be established.

9. **High — D2, S1: JSON-only is not a marshalling specification.** The bridge feeds strict JSON decoding, including nullable patches documented in Phase5. Specify rejection of undefined, functions, symbols, BigInt, cycles, nonfinite numbers and unsafe numeric IDs; distinguish omitted fields from explicit null. Bound depth and bytes before host admission, including source, parameters and returned summaries. Conversion through getters, proxies, `toJSON` or console stringification can execute JavaScript: keep it on the worker under termination control. Add adversarial conversion tests and preserve typed Swift errors plus user-source line offsets after function wrapping.

10. **Medium — D4, S1/S2: header grammar and picker semantics are incomplete.** The purported JSON header contains `//` comments, so its own example fails strict JSON parsing. Remove comments and define marker placement, duplicate/unknown fields, unique parameter names, default/type/range/step validation and missing-value behavior. `BuilderQuery` paginates scenes/clips; `BuilderDocumentSummary` selection can be a non-clip or null. Populate pickers from the captured session, including later pages, validate entity kind and project membership, and invalidate on identity/revision changes. Define zero-based tracks, finite time bounds and capture-time playhead defaults. Specify an immutable parameter object whose undeclared reads actually throw.

11. **Medium — D4/S2/S4: storage needs a concrete migration contract.** D4 correctly requires a bump: `Database.swift:642–651` skips migrations at the stamped version, currently 14. Add the table and next-version bump in the same S2 commit; update existing hard-coded 14 assertions in `DatabaseTests.swift:580–605`, alongside fresh-database, upgrade and reopen checks. Specify keys, constraints and whether source headers or duplicated metadata columns are authoritative, updating them atomically. D4 permits only `human|ai` origins while S4 installs `app`; include `app` initially or explicitly schedule another migration and version bump.

12. **Medium — Phases/Tests: phase gates omit lifecycle integration required for a clean commit.** S1 promises records and a debug runner before S2's Wizard flow, but current cancellation, identity checks, auditing and session disposal live in `WizardSheetModel` and the MCP endpoint. Put their reusable coordinator and dependencies in S1 before exposing any runner. Test dismissal/profile switching during conversion and prerequisites, no late callback after freeze, find-mode report requirements, failed-audit handling, and export after Apply clears the session. The Phase3/4/5 reports explicitly distinguish focused checks from full builds/tests; make each phase's full validation an acceptance gate rather than assuming those historical reports certify the new integration. This review ran no builds or tests.
